# 國語視覺簡報整合審核驗收

適用 `CHINESE_VISUAL_PRESENTATION`。下表是流程行為驗收情境，須以實際執行紀錄評估；Python schema／hash 測試不等於這些 ChatGPT 行為已實測。

| 情境 | 預期行為 | 不可出現 |
| --- | --- | --- |
| 新課：請做國語視覺簡報，Drive 來源齊全 | 連續找到來源、擷取、語文／成語雙軌及四層次閱讀候選，完整保存後一次 VP1 審核 | 逐頁要求繼續；四次 HOLD 1／2／2.5／2.6；先問畫布或角色 |
| 字表一處不清，其他段落可讀 | 先核對工具可解部分，完成獨立分析，再集中缺口 | 請教師逐字查證；將缺口當整包核准 |
| 教師對完整 VP1 包說確認 | 同一事件引用所展示 item／revision，保存正式選教與課程主檔，完成 VP2 方案再停 | 只說同步成功再問下一步；未展示候選自動批准 |
| VP1 只核准內容，未選四學／平板／AI／議題 | 沿用包中明示基本課程，保留日後調整入口 | 強迫選配問卷；默認四堂；把四層次閱讀當成未選 Overlay 而刪除 |
| 選四學＋平板＋AI＋預習單／短文單 | VP2 集中展示活動變更及視覺方案；學生任務回指核准內容 | 重擷取同一來源；每個活動一個 HOLD |
| 核准課程後只要先做預習單 | 共用 LKB 與 source_artifact_refs，單張完整稿審核，分支記錄不覆寫簡報 stage | 要求先完成代表頁或新角色圖；全課重跑 |
| VP2 畫布未決、角色圖不存在 | 同包提出條件式風格／角色用途／4:3 或 16:9 選項；確認後鎖方案 | 未推薦風格就被畫布阻擋；為推薦方案要求提前核准 Learning Module 候選 |
| VP3 有角色用途與位置、尚無角色圖 | 完成全文／配置／頁數／代表頁提案，存 Drive；核准為 content_approved | 假填核准資產；直接生成代表頁 |
| VP4 新角色圖已確認且只補資產引用 | 回存並驗證 Registry；保留 VP3 原稿，保存綁定差異與兩次核准，正式母稿更新 hash | 重審全課文字；偷偷更改版面／角色動作 |
| VP4 全角色已核准或不使用角色 | 核對沿用證據、完成綁定後準備代表頁組 | 空的角色確認回合；重新生成已核准圖 |
| 三種代表頁已展示，第四種未展示 | 可整組確認已展示三種，第四種仍待做 | 一個可以自動核准未展示類型 |
| 批次通過 QA，教師未確認 | 保存這一批並停等 | 自行做下一批 |
| 舊課已做到 P05，P01–P04 已核准 | 非破壞性映射 Runtime，保留核准與原頁進度；只補有影響的缺項 | 升級後退回來源擷取或重新審核所有舊稿 |

機械驗收另由 `test_grouped_review_contracts.py` 驗證同一事件可支援多項明確選教；代表頁與批次測試確認 content_approved 仍被拒絕。可執行時跑完整 repository／技能／合約測試，另查路由及資料依賴是否仍出現額外教師關卡。
