# V-MAX Source Library Policy 1.0

## 定位

本規則定義 V-MAX 如何從教師指定的 Google Drive 教科書來源庫取得原始教材，避免每課重複上傳同一本教師手冊。

核心原則：

> 原始教材集中存放；每課開工時先從來源庫找，再要求教師補檔。

> Source Library 是教材真值入口，不是成品資料夾。

---

## A. 固定來源庫

目前教師指定的 Google Drive Source Library：

`https://drive.google.com/drive/folders/1-y4EbVipODEcdLPXZnBXpCxSwqB_N2sx?usp=drive_link`

此資料夾定位為：

- 出版社原始教師手冊
- 課本／習作等原始教材
- 其他可作為教材真值的原始檔

不得將生成後的簡報、學習單、Renderer Script 或 Lesson Package 成品混入此來源庫。

正式成品仍依 `skills/lesson-package-delivery/SKILL.md` 歸檔至教師指定的 `V-MAX 教材庫`。

---

## B. 每課開工的來源順序

當教師說「做四上第 X 課」「重新開始某課」「從來源庫讀取」等，預設依下列順序：

1. 先到固定 Source Library 搜尋對應冊別／課次／課名。
2. 找到候選原始檔後，確認冊別與版本是否匹配。
3. 讀取該課所需頁面／內容，作為 STEP 1 Source Truth。
4. 若同冊有多個疑似版本、出版社版本或修訂版，先列出少量候選讓教師確認，不得靜默混用。
5. 只有來源庫找不到足以支撐 STEP 1 的原始教材時，才要求教師重新上傳或補充。

禁止：

- 明明來源庫已有檔案仍要求教師每課重新上傳。
- 只靠模型記憶或舊簡報取代原始教材。
- 因檔名相似就自行混用不同冊別／版本。

---

## C. 搜尋策略

優先以：

- 冊別，例如「四上」
- 課次，例如「第一課」
- 課名，例如「水陸小高手」
- 教師手冊／教冊／教學篇

交叉搜尋。

若教師只說「做四上第二課」，AI 應先找四上原始教師手冊，再在檔內定位第二課，不需要教師先提供檔案。

若來源檔是整冊 PDF，可直接從整冊中擷取該課，不要求拆課後再上傳。

---

## D. Source Truth 規則

來源可信度優先順序：

1. 教師指定 Source Library 中的原始教材
2. 教師本次對話明確上傳／指定的原始教材
3. 已確認的結構化轉錄來源
4. 舊成果只作參考

舊 PPT、舊 Renderer Script、舊 Source Master、模型記憶不得覆蓋原始教材真值。

若來源彼此衝突，必須標記來源差異並停在教師可理解的確認點。

---

## E. 教師端最短操作

理想使用方式：

- 「做四上第二課。」
- 「重新跑四上第一課。」
- 「從 V-MAX 教科書來源庫開始。」

AI 應自行完成：

`Drive 找冊別 → 找原始檔 → 定位課次 → STEP 1 教材定錨`

只有找不到、版本衝突或權限阻擋時才詢問教師。

核心：

> 教師負責把教材放進來源庫一次；V-MAX 負責之後每課自己找。

---

## F. 與成品庫分離

```text
Source Library
├─ 原始教師手冊
├─ 原始課本
├─ 原始習作
└─ 其他原始教材

V-MAX 教材庫
├─ Source Master MD
├─ Renderer Script MD
├─ Visual YAML MD
├─ 角色視覺資產
├─ 圖片式簡報 PDF
├─ 教學簡報 PPTX
├─ 課前預習單
└─ 課後短文學習單
```

來源庫只回答「教材原本有什麼」；成品庫保存「我們最後怎麼教」。

---

## G. 失敗處理

若 Drive connector、檔案權限或來源定位失敗：

- 回報 `SOURCE_LIBRARY_BLOCKED` 或 `SOURCE_NOT_FOUND`
- 說明缺少哪一冊／哪一課／哪個版本
- 此時才請教師補檔或指定來源

不得假裝已讀取。

---

## 核心金句

> 原始教材只上傳一次；之後每一課，V-MAX 自己去找。

> 來源庫守真值，教材庫存成果。
