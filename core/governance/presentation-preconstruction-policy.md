# 國語簡報施工前確認流程

版本：1.1
規則範圍：`GLOBAL_SKILL_RULE`

適用於 V-MAX 國語整課簡報的語文規劃、逐頁施工稿、代表頁、批次製作及續作修正。這是既有來源忠實、教師選教、State Sync、版型與文字層契約的增補，不取代它們；不強制 standalone 文件啟動整課流程。

## 1. 每次續作先同步

收到「繼續／下一步／確認／沿用」或開始新的施工階段時，先讀最新 Drive Runtime Index 與該課 Runtime State，取得 revision、目前 HOLD、教師決定及唯一 `next_allowed_stage`。進入逐頁施工及後續視覺 stage 時，同時核對課文主檔、已確認頁數帳本、Style Matrix、角色鎖定檔、畫布比例與像素尺寸、既有逐頁規則及其版本／hash。不得以聊天記憶代替。缺漏或衝突依 State Sync Gate 停住；不得自行推進。

## 2. 成語必做雙軌覆蓋檢核

STEP 2.5 的教材確認表與後續 PAGE_DETAIL_CONFIRMATION 必須分列兩份清單：

- 課文既有成語／四字詞：逐項保留來源身分、是否保留、解釋與教學頁安排；四字詞不自動判為成語。
- 生字延伸補充成語：以 Source Master 每一個正式生字為全集，逐字判斷相關成語是否可教且適齡。不得因課文已有成語頁，就視為成語教學完成。

在教師確認語文規劃前顯示「生字 → 延伸成語」覆蓋表。每列至少有 `character_ref`、生字、`decision`、成語候選與來源、適齡理由、教師選教狀態及教學位置；`decision` 為：

- `SUITABLE`：已有適合的延伸成語；仍需教師核准才能進正式選教。
- `NOT_SUITABLE`：不適合安排成語，必須寫具體理由。
- `MERGED`：與其他生字合併教學，列合併對象及同一成語頁位置。

規劃期可先填穩定的 section／item ref；PAGE_DETAIL 建立時必須補上確切 page_id，不能永久停在「稍後安排」。同一成語可共用頁，但兩軌清單與所有生字 provenance 均須保留。不得用「已有關聯詞」代替成語判讀。任一正式生字未判讀、無理由排除或合併無位置，標記 `VOCABULARY_IDIOM_COVERAGE_INCOMPLETE`，不得核准語文規劃，也不得進入逐頁施工、代表頁或生圖；既有 coverage failure codes 仍保留。

此規則明確允許逐字提出延伸成語候選，並非自動增加 Official Knowledge 或自動選教。來源未提供者標示 `[AI 延伸／待教師確認]`，核對語意與用法，經教師確認後才寫入 APPROVED_TEACHING_SELECTION；不得改寫教材原文。`N/A_NO_IDIOM` 只有在兩軌均完成判讀且教師確認無保留項目時才成立。

已核准生字補充成語安排在多音字後、結尾遷移前；未啟用多音字時，在生字／形近字單元後的成語區安排，不因此新增多音字頁。保留其他已啟用章節順序與 architecture mapping。頁數依內容決定，可一頁兩成語或按生字群分頁，仍須符合既有成語頁容量及圖文關係契約。每個保留成語均有四年級可懂的短解釋、自然正確例句與對應小插圖情境；其他年級再依鎖定年級調整難度。學生頁不放答案。

## 3. 逐頁可施工細節稿

風格、角色（包括明確不使用角色）與畫布未鎖定前，只可討論架構／風格候選，不得進入逐頁施工稿。鎖定後，先核對已確認頁數帳本，再依 `schemas/page-detail-confirmation-profile.md` 建立 `PAGE_DETAIL_CONFIRMATION`。首次尚無帳本時，先依已確認架構估頁並取得帳本確認；新增或合併頁必須形成候選修訂，不能覆寫已確認帳本。

每頁至少明列：

1. 學生可見的完整正式文字與來源。
2. 頁面教學功能。
3. 插圖功能、場景與物件內容。
4. 角色是否出場、目的、位置及鎖定資產引用；不出場也明列。
5. 文字區、圖片區、留白與禁止遮擋區。
6. 關鍵詞筆刷／底線標記計畫；沒有標記則明列不使用，實際字框於文字排版後量測。
7. 頁碼、區段及版面系統；代表頁再實測並鎖定系統 hash。

完成後設 `status: pending`、`PAGE_DETAIL_CONFIRMATION_PENDING`，保存並停等教師確認。不得直接生圖、製作投影片、建立正式 Slide Script、選代表頁或批次輸出。核准後才設 `approved`，依 Runtime 進下一個合法階段。

## 4. 代表頁逐類確認

只有已核准 PAGE_DETAIL 的頁面可被挑為代表頁。涵蓋所有實際啟用頁型，包括課文、文意／語文、生字或形近字、多音字、成語、結尾遷移，以及啟用的其他頁型。不得為湊清單加入未啟用單元；兩軌成語各自保留覆蓋回指。

每次只執行 Runtime 唯一 `next_allowed_stage`；完成即保存並停等教師確認，不因一次「確認」串跑後續階段。每類記錄代表頁、版本／hash 與核准證據，未展示／未核准頁型不得連帶通過。代表頁未逐類確認前，不得全課量產。

優先使用可用 ChatGPT 原生圖像生成／影像編輯，直接顯示工作區原生結果、保留平台提供的編輯入口與最新核准原圖引用；不得只交付 PNG 卡片、路徑或下載連結。若平台不支援，明示 `NATIVE_IMAGE_REVIEW_UNAVAILABLE` 與具體限制，提供內嵌預覽及原圖續編，不宣稱不存在的按鈕。必要文字合成仍保留原生視覺來源並直接預覽成品，不為編輯入口重生已核准內容。

## 5. 小批次製作與局部修正

代表頁各類均核准後，才依 BATCH_CONSTRUCTION_LOCK 小批次施工。每批設定 4–8 頁以內的上限，絕對不得超過 8 頁；尾批、修正批或教師要求可少於 4 頁。每批完成後即停等教師確認，即使 QA 全通過也不得自行連續下一批。

沿用已核准插圖、角色、風格、尺寸與版面規則。只修文字、字級、斷行、位置、筆刷或版面時，只調文字層／排版／標記，不得無故重新生成插圖或角色；更新文字 revision 及受影響 anchors。任何候選修改保留核准舊版，依既有 page hash 契約回寫並重新確認。

學生可見內容使用臺灣繁體中文，不放英文、答案或教師提示；來源原文與教師專用層另外忠實保存。輸出前逐頁檢查文字正確、字級清晰、文字溢位、圖片裁切、角色一致性、畫布尺寸、頁碼與版本；QA 不取代教師確認。

## 6. Runtime 與保存邊界

每完成 stage、建立 HOLD、HOLD 決策或批次停止，都非破壞性建立／更新該課 Drive Runtime State 與 Runtime Index，保留 revision、前版引用、候選／核准狀態、待確認項目、唯一 next_allowed_stage 與 forbidden_next。候選可登記為候選，但不得覆蓋已確認稿或冒充核准進度。完成回讀驗證後才宣告可接續；無法讀寫依 Runtime／Cloud Checkpoint policy 阻塞，不假稱同步。

GitHub 只保存共用規則與 schema；單課頁面內容、覆蓋表、教師決定與施工檔只存該課 Drive Runtime／施工區。教師明確要求的此類共用流程更新可登記為 GLOBAL_SKILL_RULE，不需以單課內容取代或刪除既有規則。

## 階段適用性與完整擷取

本政策的成語延伸覆蓋門檻自 STEP 2.5 起檢核，風格／角色／畫布／頁數鎖自逐頁施工前檢核。SOURCE 0／STEP 1 依 `core/governance/step1-source-anchor-policy.md` 第 G 節完整擷取教材；當前尚未產生的後段物件按 Continuation State Gate 記錄，不阻擋來源整理。一次只走一個 stage，不等於該 stage 內只讀一頁或只查一項。
