# V-MAX Lesson Knowledge Base Policy 1.0-draft

## 定位
任何預習單、短文單、正式簡報或延伸教材生成前，先由課本、教師手冊與可用補充來源建立同一份 Lesson Knowledge Base（LKB）。

> 先理解整課，再決定做什麼教材。

## LKB 最低欄位
- 課文基本資料：文體、主旨、大意、結構、作者／必要背景
- 語文知識：生字詞、形近字、多音字、成語、句型、修辭、語法
- 閱讀知識：段落功能、因果、人物、事件、推論、結構、寫作特色
- 教冊意圖：一課一重點、教學提醒、易錯點、習作／評量連結
- 背景知識：理解文本必要或高價值的文化、地理、歷史、科學、生活知識
- Student Friction：學生可能「字懂但文意不懂」的位置
- Extension Candidates：課外、跨域、平板、主題、在地等候選；收錄不等於必教
- Source Trace：每個重要事實可追溯到來源

## Content Routing
知識點不是只能去一個地方。每點可標記一個或多個目的地：
- `PREVIEW`：預習初遇
- `SHORT_READ`：短文／背景閱讀
- `CORE`：正式課堂核心
- `PLUS`：選用延伸
- `EXTENSION`：平板／跨領域／主題外掛
- `TEACHER_ONLY`：老師備課知道即可

## Learning Journey
允許同一知識螺旋式出現：
`PREVIEW → CORE_REINFORCE → RECOGNIZE → APPLY / TRANSFER`

重複必須改變認知任務，不得只是把同一題再做一次。

形近字、多音字屬典型 PREVIEW→CORE_REINFORCE：預習單先接觸，正式教材再辨析、情境判讀與應用。

## Cross-output Consistency
所有下游輸出共用：
- 核心事實與 Source Trace
- 已確認的語文範圍
- Typography Lock
- Guide Character / Visual Identity（若已成立）

但不同 Material Mode 可重新安排資訊密度與呈現方式。

## Update Rule
若教師補入新來源或修正教冊解讀，先更新 LKB，再讓下游受影響輸出重新評估；不得只在單張投影片偷偷改內容造成來源分叉。
