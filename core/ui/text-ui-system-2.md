# V-MAX Text & UI System 2.1

## 定位

Text & UI System 負責把教學內容轉成「學生看得清楚、讀得懂、知道先看哪裡」的文字與介面層。

它不負責決定教什麼，也不取代 Director Engine 的觀看路徑；它負責把已確認的教學意圖、課文內容、Knowledge Chunk 與 Visual Grammar，轉成可閱讀、可投影、可列印、可由不同 Renderer 穩定實作的文字層級與版面規則。

核心問題：

> 這頁的文字，學生能不能在幾秒內知道先看哪裡、讀什麼、做什麼？

---

## 最高原則

1. **正確性先於裝飾**：學生可見文字必須使用正式文字層，不依賴圖片模型生成中文字。
2. **認知負荷先於字數限制**：不使用僵硬的固定字數上限，改檢查一頁同時要求學生處理多少個概念與視線焦點。
3. **原文完整性優先**：課文原句、語詞、句型、修辭證據不得為了版面任意改寫。
4. **學生視線要有順序**：標題、主視覺、課文證據、提示、任務不可同時搶第一視線。
5. **少而清楚勝過滿而完整**：完整資料可以留在來源層、教師備註或後續頁，不必全部塞進學生畫面。
6. **中文排版優先**：以繁體中文閱讀習慣、標點、換行與字距為基準。
7. **Renderer 可替換，文字結構不可失真**：NotebookLM、ChatGPT、Gemini、Canva、PPT 都必須遵守同一套文字層級。
8. **教師口述優先**：學生頁只放學生此刻需要看見的文字；教師要講的完整說明、答案與備課細節放在教師層。

## A. Text Layers｜文字層級

學生畫面預設只使用必要層級，不要求每頁全部出現。

### T1｜Page Purpose / Title
- 一眼說明這頁在做什麼。
- 優先使用教學語意標題，而不是抽象裝飾標題。
- 避免同一頁同時出現主標、副標、章節名、任務名四層標題。

### T2｜Primary Learning Text
本頁主要學習內容，例如：
- 課文原句
- 關鍵語詞
- 生字／字群
- 成語
- 句型骨架
- 問題核心

此層應取得最高閱讀優先權。

### T3｜Evidence / Support
支援理解的第二層資訊，例如：
- 原文證據
- 差異部件
- 詞義提示
- 情境線索
- 修辭效果
- 例句

若 T3 超過 2–3 組互不相關資訊，應檢查是否拆頁或改成逐步 Reveal。

### T4｜Prompt / Student Action
學生此刻要做什麼：
- 找
- 比
- 說
- 猜
- 排
- 改
- 寫
- 選

任務語句要短、清楚、可執行；不要把教師講稿直接放進學生任務框。

### T5｜Micro Annotation
必要的小型輔助資訊，例如：
- 注音
- 詞性
- 來源標籤
- 小提示
- 編號

Micro Annotation 不得因為字太小而成為「看得到但讀不到」的裝飾文字。

## B. Cognitive Load｜認知負荷規則

### 核心判準

不是問「這頁有幾個字」，而是問：

- 學生同時要辨識幾個概念？
- 要在幾個區塊之間來回看？
- 是否同時要求閱讀、比較、推論、作答？
- 是否存在兩個以上競爭第一視線的焦點？

### 預設規則

- 一頁以 **1 個主要認知任務** 為原則。
- 可搭配 1 個次要任務，但不得同時要求 3 個以上主要動作。
- 若內容必須完整保留，可用 progressive reveal、分步、同場比較或後續頁，而不是縮小全部文字。
- 禁止用「字變小」解決內容過量。

### Overload Signals
符合任一項即需檢查：
- 標題下面立刻有三大段以上說明文
- 四個以上卡片各自有完整句段
- 主圖、角色、對話框、課文原文、任務框同時搶畫面
- 課文原句被縮到與註解差不多大
- 學生需要超過 3 次視線跳轉才能完成單一任務
- 同頁同時出現課文、語詞、修辭、句型、深究、練習、小提醒與小挑戰中的三類以上
- 畫面出現書寫線、填空區或大面積作答空白，卻被標示為簡報頁而非學習單

## C. Chinese Typography｜中文排版

### 基本規則
- 使用繁體中文正式字形。
- 句讀依原文或正式中文標點，不任意轉成英文標點。
- 學生可見標音只允許台灣繁體注音符號；不得出現拼音、英文標音、日文假名或不明亂碼標音。
- 中文正文避免過度拉寬字距。
- 行長以可快速掃讀為原則，不做超長橫向文字牆。
- 詩歌、對話、條列、課文原段落應保留其原本節奏，不為了塞版面強制合併。
- 不把每個詞切成不同色塊，除非顏色本身承擔辨識功能。

### 換行
- 優先在語意完整處換行。
- 避免把固定詞語、成語、專名拆行。
- 句型骨架若需標示結構，可用視覺分節，但原句仍須可還原閱讀。

### 強調方式
優先順序：
1. 位置與留白
2. 字級／粗細
3. 框線或底色
4. 少量強調色

不得只靠大量不同顏色製造層級。

---

## D. Font Size Policy｜字級政策

V-MAX 不把單一 pt 數寫死給所有 Renderer，但要求明確的相對層級。

### 投影簡報建議層級
- Title：最大
- Primary Learning Text：接近 Title 或明顯大於正文
- Evidence / Support：可從教室後排舒適閱讀
- Annotation：不得小到只能近距離觀看

### 生成前檢查
- 若需要縮小正文才能塞下內容，優先重構內容。
- 課文原句、關鍵語詞、字群比較不得成為頁面最小字。
- 學生任務文字必須比來源註記、教師備註更醒目。

Renderer Adapter 可將此相對層級映射成實際 pt / px / rem。

---

## E. Source Quote Integrity｜課文原文與證據

### 原文
- 課文原句／原段若標記為 `source_quote`，不得自行潤飾、改詞、補字或刪節到改變語意。
- 若因版面只擷取部分句子，需保留可辨識的原文範圍，必要時標示省略。
- 句型與修辭頁必須保留足夠上下文，避免只剩孤立片語。

### 教學改寫
若要提供：
- 白話解釋
- 改寫句
- 錯誤例句
- 仿作句

必須與原文視覺上清楚區隔，不得混成作者原句。

---

## F. Zhuyin Policy｜注音政策

### 核心原則

注音是正式文字資訊，不交給圖片模型生成。

### 使用條件
- 只有教學需要、教材來源有提供、或教師指定時顯示。
- 生字／多音字／易讀錯字可使用。
- 不預設全頁、全文、所有成語都加注音。
- 課文閱讀頁原則上不標注音；若教師要求或教材需要，僅標示識別字，不標整段。

### 正確性
- 優先依教材與正式來源資料。
- 多音字必須綁定語境，不可只顯示脫離詞義的音表。
- 聲調與注音符號不可由圖像生成模型猜測。

### 視覺
- 注音不得擠壓主字到失去辨識度。
- 同場字群比較時，注音位置需一致。

---

## G. Text Inside Images｜圖片中文字

### 禁止作法
- 讓生成式圖片直接生成課文、注音、生字、成語定義、題目文字。
- 把含有錯字風險的 AI 圖中文字當成正式教學內容。

### 正確作法

```text
Image Layer：情境、人物、物件、視覺關係
Text Layer：正式中文字、注音、標籤、題目、解釋
```

若視覺中需要路牌、標示牌、對話框等中文，Renderer 應後製正式文字層。

---

## H. Task UI｜學生任務介面

### 任務框原則

一個任務框只說明一個主要動作。

好：
> 找一找：哪兩句寫出了「轉得很快」？

避免：
> 請閱讀課文後找出相關語詞、討論作者運用的修辭、說明效果，並和同學分享你的感受。

若任務包含多步，應顯示清楚步序：

```text
① 找證據
② 比一比
③ 說發現
```

而不是塞成一段指令。

### 答案
- 學生版預設不直接顯示答案。
- 可用 delayed / progressive reveal。
- 教師答案放講者備註、教師版或答案層。

---

## I. Comparison UI｜比較頁

形近字、多音字、詞義差異、前後變化等比較內容：

- 比較項目需同場可見。
- 對齊相同欄位，降低視線跳轉。
- 相同之處與不同之處視覺上分層。
- 不把每個比較項目做成彼此無關的裝飾卡片。
- 差異部件、讀音、語意、例詞的位置盡量固定。

核心：**先讓眼睛看出關係，再讓文字命名關係。**

---

## J. Poetry UI｜童詩排版

童詩不套一般說明文版型。

- 保留行分、節奏、重複與留白。
- 不為填滿畫面把詩句拆散成許多卡片。
- 若要分析重複、句型、意象，可另做分析層，但原詩閱讀頁先保留完整閱讀感。
- 想像畫面與詩句之間應形成呼吸，不讓分析標籤蓋過詩本身。

---

## K. Teacher Layer vs Student Layer｜教師層與學生層

### Student Layer
只放學生當下需要看到的：
- 文本
- 視覺證據
- 任務
- 必要提示
- 學習整理

不得把教師口述講稿、完整解析、標準答案、來源細節或備課提醒塞進學生頁，只因為投影片還有空位。

### Teacher Layer
放：
- 標準答案
- 教學意圖
- 追問
- 常見迷思
- 替代活動
- 來源說明
- Renderer 備註

禁止為了「資料完整」把教師備課資訊塞到學生畫面。

## L. UI Density Modes｜介面密度

依 Shot Function 選擇，不由風格決定。

### `immersive`
- 少文字、大視覺、留白多
- 適合 ENTER、PAUSE、童詩意象、高潮停格

### `balanced`
- 文圖並重
- 適合段落理解、語詞、句型、修辭

### `analytic`
- 對齊、比較、圖解清楚
- 適合形近字、多音字、說明結構、證據整理

### `practice`
- 題目與作答空間清楚
- 減少裝飾
- 適合練習、評量、仿作

教師口述型簡報中的仿作頁仍以口頭發想與圖像引導為主；若需要長書寫線或作答區，應改交由學習單承接。

Style Recipe 不得強迫所有頁面使用同一密度。

```yaml
  layers:

    mode: open | guided | delayed | progressive | hold

    answer:
    notes:

    no_text_in_generated_image: true

```

## N. Quality Check｜文字與介面檢核

每頁至少檢查：

- 3 秒內是否知道這頁要看什麼／做什麼？
- 第一視線是否唯一且合理？
- 課文原文是否正確保留？
- 文字是否因塞內容而縮太小？
- 是否有 3 個以上主要認知任務？
- 任務語句是否可直接執行？
- 注音是否必要、正確、可讀？
- 圖片裡是否混入不可控的中文字？
- 教師答案是否誤出現在學生頁？
- 留白是否足夠形成層級？
- Style 是否搶走 Content 的閱讀權？

任一核心項不通過，Renderer 不得用「美化」掩蓋問題。

---

## 與其他模組的關係

```text
Director Engine
↓
Visual Grammar / Visual Sequence
↓
Knowledge Chunk
↓
Text & UI System
↓
Layout + Style Recipe + Character System
↓
Renderer Adapter
↓
Text UI Quality Check
```

Text & UI System 決定的是「學生如何讀」，不是「畫面看起來是哪一種風格」。

---

## 核心金句

> 不是限制一頁能放多少字，而是限制一頁要孩子同時處理多少件事。

> 文字不是填補畫面的材料，而是學生理解路徑的一部分。

> 圖片可以有想像力，教學文字必須可驗證。
