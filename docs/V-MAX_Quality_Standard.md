# V-MAX Quality Standard（VQS）

版本：1.0.0

## 目的

VQS 是 V-MAX 所有 Baseline Lesson Package、Adaptive Patch 與 Classroom Variant 的共同品質標準。任何成果在標記為完成前，都必須通過對應層級的檢查。

VQS 不取代教師專業判斷，而是確保教材忠實、教學可用、視覺可讀、數位活動可執行、版本可追溯。

## 品質狀態

- `pass`：全部必要項目通過。
- `conditional_pass`：核心項目通過，但仍有已揭露的非阻斷缺口。
- `needs_revision`：有阻斷性問題，不能交付或進入下一階段。
- `not_applicable`：本課或本輸出不適用，必須附原因。

## A. 教材忠實與完整性

### 必須通過

- 課文原文、標點、段落與順序一致。
- 生字與認讀字完整且正確分流。
- 全部核心詞語完整列出，不得只挑代表性詞語。
- 教材明示的成語、詞義、例句與對應生字完整保留。
- 教材明示的修辭、句型、寫作特色、主旨、結構與教學重點完整保留。
- 教師手冊、習作與出版社資源的來源清楚標記。
- AI 延伸未冒充官方教材內容。
- 未混入其他課次資料。

### 阻斷條件

- 課文被改寫。
- 官方成語被新增、刪除或改寫。
- 核心詞語、認讀字或教材活動有缺漏。
- 官方內容與系統延伸來源混淆。

## B. LKB 與知識追溯

- LKB 為本課唯一知識主檔。
- 每個重要知識節點具有來源檔案與頁碼或區塊。
- 重複知識已整合，但原始來源均被保留。
- 教師知識、學習延伸與官方知識分層清楚。
- 所有派生輸出記錄 LKB 版本與引用節點。
- 修改派生輸出時，不得取代上游知識修正。

## C. 教學設計品質

- Learning Modules 只掛載核准的 LKB 節點。
- Learning Path 符合年級、教材特性與能力目標。
- Teaching Flow 先於投影片頁數決定。
- 每節課具有清楚目標、時間、教師行動、學生任務與檢核方式。
- 每頁或每個活動原則上只有一個主要學習焦點。
- Support、Challenge、Mission 與 Core 分流清楚。
- 成語易誤用、近義辨析、情境練習等均標記為學習延伸。

## D. 視覺與閱讀品質

- 字級符合目標年級，不能以縮小字體解決內容過多。
- 文字、插圖與版面具有清楚視覺層級。
- 插圖具備教學功能，不是裝飾性截圖。
- 成語插圖符合實際語意，不只呈現字面。
- 角色、風格與教材情緒協調。
- Bee 老師或其他角色不遮擋教材重點。
- 每張投影片的版型與 Layout DNA 一致。
- 不出現未替換變數、重複 `slides` 節點或版面溢出。

## E. 教師版與學生版分流

### 學生版不得出現

- 教師答案。
- 參考解答。
- 講者備註。
- 內部節點 ID。
- 驗證訊息。
- 系統 Prompt 或來源路徑。

### 教師版應包含

- 必要答案與解題依據。
- 教學提醒與差異化支援。
- 平板活動操作與替代方案。
- 必要的來源與版本資訊。

## F. 平板與數位互動品質

- 平板活動具有明確學習目標與學生產出。
- 每節原則上不超過兩個主要平板活動。
- 單一活動建議控制在 3～10 分鐘。
- 每個數位活動均有紙本、口頭或無裝置替代方案。
- 活動結束後有回到全班討論或統整的步驟。
- 不蒐集不必要的學生個人資料。
- 未建立實際網址時標記 `LINK_PENDING`，不得虛構連結。
- QR Code、短連結與操作步驟可讀且可測試。

## G. NotebookLM 與派生輸出品質

- NotebookLM Source 具備連續、清楚、可讀的章節結構。
- 官方知識與學習延伸標記清楚。
- 圖文簡報生成指令包含角色、風格、版型、配色、字級與插圖要求。
- 指令不得重複建立 `slides` 根節點。
- 修改投影片後仍保留角色 DNA、Style DNA 與答案分流。
- Curated Briefing 只作為派生輸出，不得成為新的唯一知識來源。

## H. Baseline Package 完成標準

Baseline 只有在下列必要成果存在並通過檢查時，才能標記為 `baseline_completed`：

1. Lesson Knowledge Book。
2. 官方知識驗證報告。
3. Learning Modules。
4. 核准的 Learning Path 與 Teaching Flow。
5. 完整教學簡報腳本或簡報成果。
6. 教師講者備註與答案分流。
7. NotebookLM Source。
8. Output Manifest。
9. VQS 驗證報告。

依教材推薦但非強制的成果，可標記為 `not_generated` 並附原因，例如學習單、平板活動、Exit Ticket。

## I. Patch 與 Classroom Variant 品質

### Patch

- 記錄來源 Baseline Version。
- 明確標示 `add_on`、`replace` 或 `reflow`。
- 只修改必要範圍。
- 記錄受影響節點、頁面、活動與版本。
- 不直接覆蓋 Baseline。

### Classroom Variant

- 記錄 Baseline 與套用的 Patch。
- 說明實際授課時間、班級條件與裝置模式。
- 選用、省略與替換內容可追溯。
- 快速版或無裝置版仍須保留核心學習目標。

## J. Teaching Memory 品質

- Teaching Memory 綁定實際使用版本。
- 不記錄學生姓名、座號、照片或可識別個資。
- 教師反思區分單次觀察與穩定趨勢。
- 單次反思不得自動改寫 LKB 或 Baseline。
- Lesson Evolution 的長期建議須有多次紀錄支持。

## 最終阻斷清單

以下任一情況存在時，不得交付：

- 官方教材內容有缺漏或未標示改寫。
- 學生版答案外洩。
- 核心詞語或認讀字未完成核對。
- 非教材成語混入官方成語清單。
- 角色、風格或 Teaching Flow 尚未核准。
- 平板活動無替代方案。
- Output Manifest 無法追溯來源版本。
- 存在未替換變數、重複節點或嚴重版面溢出。

## 驗收原則

VQS 驗證應以「必要項目全部通過」為完成條件，不採總分抵銷。視覺美感高分不能抵銷教材缺漏，活動豐富也不能抵銷學生版答案外洩。
